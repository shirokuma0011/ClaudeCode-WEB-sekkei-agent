# 全工程共通ルール

このファイルは、`CLAUDE.md` のマスターエージェントと `.claude/agents/` 配下のすべてのサブエージェントが従う共通ルールである。各サブエージェントは作業開始前にこのファイルを読む。

## 情報の確度を分離する

- ユーザー提供情報、合理的な仮設定、要確認事項を必ず区別する。
- 仮設定には `[仮設定]`、公開前に事業者の確認が必要な項目には `[要確認]` を付ける。
- 所在地、営業時間、料金、資格、受賞歴、顧客数、導入実績、レビュー、効果、統計を捏造しない。
- 不足情報は設計を止めない範囲で仮設定できるが、公開用コピーでは事実として断定しない。
- 医療、健康、法務、金融、保険などの高リスク分野では、結果保証、誇大表現、無根拠な比較優位を作らない。公開前の専門家確認事項を明示する。
- 個人情報は必要最小限にし、実データや秘密情報をサンプルへ埋め込まない。

## 引き継ぎの原則

- 前工程の成果物を次工程の唯一の引き継ぎ元とする。会話履歴や推測に頼らず、`output/<project-slug>/` 内のファイルを読んで作業する。
- 矛盾を見つけた場合は、下流で辻褄を合わせるのではなく、上流成果物を修正して整合させる。修正した場合は最終報告に含める。
- 各工程は「完了条件」を満たしてから終了する。満たせない場合は、何が不足しているかを報告して終了する。

## 品質基準

- 業種とCVに合わせた5ページ以上の情報設計にする。
- モバイルファーストで、キーボード操作、フォーカス表示、十分なコントラスト、フォームラベル、代替テキストを設計する。WCAG 2.2 AAを目標とする。
- SEOは検索意図、ページ別title/description、見出し構造、内部リンク、構造化データ候補まで具体化する。ただし検索順位を保証しない。
- CTAは主目的と副目的を分け、各ページに適切に配置する。
- 画像プロンプトは英語でちょうど10件作り、原則 `no text, no letters, no logos, no watermark` を含める。
- 実在人物や既存ブランドを模倣させず、人物を扱う場合は多様性、自然さ、プライバシーに配慮する。
- JavaScriptは段階的機能向上を基本とし、無効でも主要情報と導線を利用できるようにする。
- アニメーションは `prefers-reduced-motion` を尊重する。
- 外部スクリプト、解析、Cookie、フォーム送信先はユーザーが指定しない限り接続しない。

## ファイル操作と安全性

- `<project-slug>` は英小文字、数字、ハイフンのみで1〜64文字とする。
- 成果物の出力は必ずリポジトリ内の `output/<project-slug>/` に限定する。リポジトリ本体（`docs/`、`scripts/`、`.claude/` など）は成果物生成中に変更しない。
- 既存成果物を上書きする場合は対象を確認し、ユーザーの無関係な変更を消さない。`--force` は上書きしてよいと確認できた場合のみ使う。
- ZIPにZIP自身、`node_modules`、秘密情報、環境変数ファイル、Git管理情報を含めない。
- `.env`、鍵ファイル、認証情報を読み取らず、成果物やログに書き出さない。

## 画像の扱い

- Claude Code自体には画像生成機能がない。標準は「プロンプトのみモード」であり、`assets/images/README.md` にその旨を明記する。
- ユーザーが画像生成手段（外部ツールやAPI）を用意し、生成した10枚を `assets/images/` に指定ファイル名で配置した場合のみ「画像ありモード」として検証する。
- 画像を生成していないのに生成したと表現してはならない。

## 表記

- 成果物は日本語で書く。ただし画像プロンプトは英語、ファイル名・URL・コードは英数字とする。
- 見出しは階層を飛ばさない。表は列数を揃える。
