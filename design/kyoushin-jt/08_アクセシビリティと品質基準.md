# 08. アクセシビリティと品質基準

## 1. 準拠目標

**JIS X 8341-3:2016（＝WCAG 2.1）レベルAA 準拠**

住宅・不動産の主要検討層には50〜60代が多く含まれます。
アクセシビリティ対応は「特別な配慮」ではなく、
**老眼・手元の不安定さ・屋外での画面の見えにくさといった一般的な条件下での使いやすさ**に直結します。

---

## 2. 実装要件

### 2.1 知覚可能

| 要件 | 実装 |
|---|---|
| 画像の代替テキスト | 全画像に `alt`。内容を説明する文章にする（05章7.3）。装飾は `alt=""` |
| コントラスト | 本文 4.5:1 以上、大きい文字・UI部品 3:1 以上。**05章2.2で実測検証済み** |
| 色だけに頼らない | 物件ステータスは色＋テキスト。エラーは色＋アイコン＋文言 |
| テキストの拡大 | 200%拡大しても内容が失われない。`user-scalable=no` を**使わない** |
| 文字画像 | ロゴ以外でテキストを画像化しない（キャッチコピーもHTMLで） |
| 動画 | 使用する場合は字幕を付与 |
| 情報と関係性 | 見出し・リスト・テーブルを正しいHTML要素で表現 |

### 2.2 操作可能

| 要件 | 実装 |
|---|---|
| キーボード操作 | 全機能をキーボードのみで操作可能。マウス必須の操作を作らない |
| フォーカス可視 | `:focus-visible` で3px以上のアウトライン。**`outline: none` 禁止** |
| フォーカス順序 | DOM順＝視覚順。`tabindex` に正の値を使わない |
| スキップリンク | 「本文へスキップ」をページ先頭に（フォーカス時のみ表示） |
| タップターゲット | 最小44×44px、間隔8px以上 |
| 自動再生 | カルーセルの自動再生をしない。動画は `autoplay` しない |
| タイムアウト | フォームに時間制限を設けない |
| モーション | `prefers-reduced-motion` を尊重（05章8節） |

```html
<!-- スキップリンク -->
<a href="#main" class="skip-link">本文へスキップ</a>
```
```css
.skip-link { position:absolute; left:-9999px; }
.skip-link:focus { left:8px; top:8px; z-index:100; background:#fff; padding:12px; }
```

### 2.3 理解可能

| 要件 | 実装 |
|---|---|
| 言語指定 | `<html lang="ja">` |
| ラベル | 全入力欄に `<label for>`。プレースホルダーをラベル代わりにしない |
| エラー識別 | エラー箇所を特定し、**修正方法を文章で**示す（「電話番号はハイフンなしで入力してください」） |
| 一貫性 | ナビゲーションの位置・順序を全ページで統一 |
| リンクテキスト | 「こちら」「詳細」だけにしない。「物件一覧を見る」のように目的が分かる文言に |
| 専門用語 | 「建築条件付売地」「UA値」「C値」「BELS」には初出時に1行の説明を添える |

> 最後の項目は、アクセシビリティであると同時に**コンバージョンにも直結**します。
> 意味の分からない言葉が並ぶページからは、人は静かに離脱します。

### 2.4 堅牢

| 要件 | 実装 |
|---|---|
| 妥当なHTML | W3Cバリデータでエラー0。ID重複・タグの閉じ忘れをなくす |
| 名前・役割・値 | カスタムUIには適切なARIA。**まずネイティブ要素を使う**（`<button>` を `<div>` で作らない） |
| 状態の通知 | ハンバーガーは `aria-expanded`、絞込み結果の更新は `aria-live="polite"` |

```html
<button aria-expanded="false" aria-controls="gnav" class="menu-toggle">
  <span class="visually-hidden">メニューを開く</span>
</button>
<nav id="gnav" hidden>…</nav>

<!-- 絞込み結果件数 -->
<p aria-live="polite">条件に合う物件が <strong>12</strong> 件見つかりました</p>
```

## 3. 検証方法

| 手段 | 対象 | 頻度 |
|---|---|---|
| axe DevTools / Lighthouse | 自動検出可能な項目 | 全テンプレート、実装時 |
| キーボードのみ操作 | 主要導線5本（トップ→物件→問い合わせ送信 等） | リリース前 |
| スクリーンリーダー | NVDA（Win）または VoiceOver（Mac/iOS）でトップ・物件詳細・フォーム | リリース前 |
| 200%拡大表示 | 全テンプレート | リリース前 |
| 実機モバイル | iPhone / Android 各1台。屋外の明るさでも確認 | リリース前 |

> **自動チェックだけでは不十分です。** axe等が検出できるのはWCAG項目の3〜4割程度で、
> 「altが内容を説明しているか」「リンク文言が目的を表しているか」は人間が見る必要があります。

## 4. 受入基準（検収条件）

以下をすべて満たすことをリリース条件とします。

### 4.1 必須（未達ならリリースしない）

- [ ] Lighthouse: Performance ≥ 90 / Accessibility ≥ 95 / Best Practices ≥ 95 / SEO ≥ 95（モバイル）
- [ ] Core Web Vitals: LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1（主要5テンプレート）
- [ ] 性能予算（06章4節）を全テンプレートで充足
- [ ] axe DevTools で Critical / Serious の指摘が 0件
- [ ] キーボードのみで主要導線5本を完走できる
- [ ] W3C HTMLバリデータのエラー 0件
- [ ] 旧URL全件から新URLへ 301 が機能（リダイレクトチェーンなし）
- [ ] 全ページに一意の title / description / canonical
- [ ] 構造化データがリッチリザルトテストでエラー0
- [ ] フォームが3系統のメール（Gmail / Outlook / キャリア）に到達
- [ ] 宅建業法の法定表示が物件詳細テンプレートに全項目実装され、入力必須になっている
- [ ] 320px幅で横スクロールが発生しない
- [ ] 全画像に `width` / `height` 属性と適切な `alt`

### 4.2 推奨

- [ ] スクリーンリーダーで物件詳細の内容が理解できる
- [ ] 200%拡大で全機能が使える
- [ ] 実機3端末以上で目視確認
- [ ] 印刷スタイル（物件詳細を紙に出して持ち歩ける）

## 5. 品質を維持する運用ルール

リリース後に品質が劣化する典型的な原因と、その予防策です。

| 劣化の原因 | 予防 |
|---|---|
| 巨大な画像がそのままアップされる | CMS側で**自動リサイズ・WebP変換**を実装。担当者の注意力に頼らない |
| `alt` が入力されない | 画像フィールドで `alt` を**入力必須**にする |
| 見出しを装飾目的で使う | 編集画面で使える見出しを h2・h3 に制限する |
| プラグイン追加で速度低下 | 追加時に Lighthouse を再測定するルールを運用マニュアルに明記 |
| 法定表示の記入漏れ | 物件フィールドのバリデーション（06章2.1） |
| 成約済物件が残り続ける | `next_update`（次回更新予定日）超過の物件を管理画面で警告表示 |

> 最後の項目は運用上とても重要です。
> **古い物件情報が残っているサイトは、それだけで信用を失います。**
> 「更新予定日を過ぎた物件が3件あります」とダッシュボードに出す仕組みを、
> 最初から組み込んでおいてください。
