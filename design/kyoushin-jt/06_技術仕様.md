# 06. 技術仕様

## 1. CMS選定

### 1.1 評価

現行は Jimdo系ノーコードCMSと推定（00章 P-1）。課題A-1（URL）とA-3（物件DB化）は
**現行CMSのままでは構造的に解決できません**。移行が前提となります。

| 候補 | 初期費用 | 月額目安 | URL自由度 | 物件DB | 社内更新 | 総合 |
|---|---|---|---|---|---|---|
| **WordPress（カスタム投稿型）** | 中 | 低（サーバ代のみ） | ◎ | ◎ ACF等で構築 | ◎ | **◎ 推奨** |
| ヘッドレスCMS + SSG<br>(microCMS + Astro/Next.js) | 高 | 中 | ◎ | ◎ | ○ | ○ |
| 不動産特化SaaS<br>(いえらぶCLOUD等) | 中 | 高 | △ | ◎ | ◎ | △ |
| 現行CMSのまま改善 | 低 | 低 | ✗ | ✗ | ◎ | ✗ |

### 1.2 推奨: WordPress（カスタム投稿タイプ構成）

**選定理由**

1. **物件・事例をレコードとして持てる** — 課題A-3の唯一の根本解決。
2. **URLを完全に制御できる** — 03章のURL設計をそのまま実装可能。
3. **社内で更新できる** — 地方工務店の運用実態に合う。後任への引き継ぎも容易。
4. **制作会社を乗り換えられる** — 特定ベンダーへのロックインが最も小さい。
5. **不動産・住宅系のプラグイン資産が豊富** — 物件検索・地図・フォームなど。

**留意点と対策**

| リスク | 対策 |
|---|---|
| 表示速度が遅くなりがち | ページキャッシュ（WP Rocket等）＋ 画像最適化 ＋ 不要プラグインを入れない（上限12個を目安） |
| セキュリティ | 自動更新、WAF、2要素認証、ログイン試行制限、管理画面のIP制限 |
| プラグイン依存 | 主要機能（物件・事例）はテーマ側に実装し、プラグインに依存させない |

> **ヘッドレス+SSGを選ぶ場合**: 速度・セキュリティで優位ですが、
> 社内担当者が「プレビューを見ながら直す」体験が劣ります。
> 更新頻度が高い物件情報を扱う本件では、**運用しやすさを優先してWordPressを推奨**します。

## 2. データモデル

### 2.1 物件（カスタム投稿タイプ `property`）

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `property_id` | 数値 | ✓ | URLに使用。自動採番 |
| `title` | 文字列 | ✓ | 例「【新築分譲】八王子市八木町 3LDK」 |
| `status` | 選択 | ✓ | 販売中 / 商談中 / 成約済 |
| `type` | 選択 | ✓ | 新築分譲 / 売地 / 建築条件付売地 / 駐車場 / 中古 |

| `access` | 繰返し | ✓ | 路線 / 駅 / 徒歩分（80m=1分で算出） |
| `land_area` | 数値(m²) | ✓ | 坪換算は自動表示 |
| `building_area` | 数値(m²) |  | 土地のみの場合は空 |
| `layout` | 選択 |  | 1LDK〜5LDK以上 |
| `structure` | 文字列 |  | 木造2階建 等 |
| `built_date` | 日付 |  | 完成/築年月 |
| `use_district` | 文字列 | ✓ | 用途地域 |
| `bcr` / `far` | 数値(%) | ✓ | 建ぺい率 / 容積率 |

| `building_condition` | 真偽 |  | 建築条件付きか |
| `featured` | 真偽 |  | 「おすすめ物件」フラグ（旧 `/20190518144118` の代替） |

> **入力必須のバリデーションを実装**してください。不動産広告の法定表示であり、
> 人間の注意力に頼ると必ず漏れます。

## 3. インフラ構成

```
[ユーザー]
    │ HTTPS (HSTS)
[CDN / WAF]  ← Cloudflare等。画像配信・キャッシュ・DDoS防御
    │
[Webサーバ]  ← 国内レンタルサーバ（PHP 8.2+ / MySQL 8 / HTTP/2以上）
    ├ WordPress（ページキャッシュ有効）
    └ 日次バックアップ（サーバ外に保管）
```

| 項目 | 仕様 |
|---|---|
| ドメイン | `www.kyoushin-jt.co.jp` を正とし、非www・httpは301 |
| SSL | 常時HTTPS、TLS 1.2以上、HSTS（max-age 1年）、自動更新 |
| PHP | 8.2 以上 |
| メール送信 | **SMTP経由**（`mail()` 直送は迷惑メール判定されます）。SPF / DKIM / DMARC を設定 |
| メールアドレス | `info@kyoushin-jt.co.jp` へ移行（課題A-8）。旧アドレスは一定期間転送 |
| ステージング | 本番と別環境を用意。本番への直接編集を禁止 |

## 4. 性能予算（バジェット）

超過した場合は**リリースしない**、という基準です。

| 項目 | トップ | 物件詳細 | 一覧 |
|---|---|---|---|
| 総転送量（初回・モバイル） | ≤ 1.5MB | ≤ 1.8MB | ≤ 1.2MB |
| HTMLサイズ | ≤ 80KB | ≤ 100KB | ≤ 90KB |
| CSS（クリティカル以外含む） | ≤ 80KB | ≤ 80KB | ≤ 80KB |
| JavaScript | ≤ 150KB | ≤ 200KB | ≤ 150KB |
| Webフォント | ≤ 300KB | 同左 | 同左 |
| リクエスト数 | ≤ 50 | ≤ 60 | ≤ 55 |
| LCP（モバイル4G） | ≤ 2.5s | ≤ 2.5s | ≤ 2.5s |
| INP | ≤ 200ms | ≤ 200ms | ≤ 200ms |
| CLS | ≤ 0.1 | ≤ 0.1 | ≤ 0.1 |

### 4.1 達成のための実装ルール

1. **画像**: 05章7節の仕様を厳守。アップロード時にサーバ側で自動リサイズ・WebP生成。
2. **フォント**: ウェイトは2つまで。`font-display: swap`。サブセット化。
3. **JavaScript**: jQuery依存のプラグインを避ける。地図・スライダーは必要時に動的読み込み。
4. **サードパーティ**: タグは GA4 のみを基本とする。
   チャットツール・ヒートマップ等は**1つ追加するたびに性能予算を再測定**。
5. **CSS**: クリティカルCSSをインライン化、残りは `preload` で非同期。
6. **キャッシュ**: 静的アセットは `Cache-Control: max-age=31536000, immutable` ＋ファイル名にハッシュ。

## 5. セキュリティ

| 項目 | 仕様 |
|---|---|
| ヘッダー | `Strict-Transport-Security` / `X-Content-Type-Options: nosniff` / `Referrer-Policy: strict-origin-when-cross-origin` / `Content-Security-Policy`（段階導入） |
| 管理画面 | URL変更、2要素認証、ログイン試行5回で一時ロック、可能ならIP制限 |
| 権限 | 編集者（物件・事例の更新）と管理者を分離。日常運用は編集者権限で行う |
| フォーム | CSRFトークン、reCAPTCHA v3、送信レート制限、入力値サニタイズ |
| 個人情報 | フォーム送信内容をDBに保存しない（メール転送のみ）か、保存する場合は保持期間を定めて自動削除 |
| 更新 | WordPress本体・プラグインの自動更新を有効化。月次で稼働確認 |
| バックアップ | 日次フルバックアップ、30世代保持、**復旧手順の年1回のリハーサル** |

## 6. 移行時の技術チェックリスト

- [ ] 旧サイトの**全URL**を棚卸し（`tools/fetch-site-assets.sh` が一覧を生成）
- [ ] 301リダイレクトを全件設定（03章5節）。リダイレクトチェーンを作らない（旧→新の1ホップ）
- [ ] `sitemap.xml` を新URLで生成し、Search Console に送信
- [ ] `robots.txt` を確認（ステージングの `Disallow: /` を**本番に持ち込まない**）
- [ ] 全ページに `canonical` を自己参照で設定
- [ ] 絞込みクエリ付きURL（`?type=` 等）は `canonical` を一覧トップへ
- [ ] 成約済物件は `noindex, follow`
- [ ] GA4 の測定IDを本番に設定、旧サイトのデータと期間を繋いで比較できるようにする
- [ ] Search Console に新サイトを登録、**旧URLのインデックス減少と新URLの増加を4週間追跡**
- [ ] 主要ページのスクリーンショットを移行前に保存（差分確認・トラブル時の証跡）
- [ ] メール到達テスト（Gmail / Outlook / 携帯キャリア宛の3系統）
