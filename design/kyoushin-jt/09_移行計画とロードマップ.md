# 09. 移行計画とロードマップ

図版: `assets/diagrams/roadmap.svg`

---

## 1. 進め方の基本方針

**一括リニューアルではなく、効果の出る順に段階実施します。**

理由は3つです。

1. 現状のKPIベースラインが未取得のため、まず**計測基盤を入れて現状を知る**必要がある
2. 課題A-2（title）のように、**現行CMSのままでも即日改善できるもの**がある
3. 物件DB化（A-3）は工数が大きく、先行して**投資判断の材料**を得たい

---

## 2. フェーズ計画

### Phase 0 — 現状把握と応急処置（2〜3週間）

> **目的: ベースライン取得と、低コストで効く改善の先行実施**

| # | 作業 | 担当 | 工数目安 |
|---|---|---|---|
| 0-1 | GA4 / Search Console を現行サイトに設置 | 制作 | 0.5日 |
| 0-2 | 実機監査（`tools/audit-checklist.md` の V-1〜V-10 を全件埋める） | 制作 | 2日 |
| 0-3 | 全URLの棚卸し（`tools/fetch-site-assets.sh` 実行） | 制作 | 0.5日 |
| 0-4 | 現行サイトの画像を全件取得・棚卸し | 制作 | 0.5日 |
| 0-5 | **全ページのtitle / descriptionを書き換え**（07章2節） | 制作 | 1日 |
| 0-6 | NAP（住所・電話）の正を確定し、サイト内を統一 | 発注者＋制作 | 0.5日 |
| 0-7 | Googleビジネスプロフィールの整備 | 制作 | 0.5日 |
| 0-8 | 重複ページ（Renovation×2、ステイブルハウス×2）の統合 | 制作 | 1日 |

> **0-5 だけでも効果があります。** 現行CMSのままtitleを直すだけで、
> 検索結果でのクリック率が改善する可能性が高い項目です。
> 以降のフェーズの投資判断材料にもなります。

**Phase 0 の成果物**: 現状レポート（KPIベースライン＋実機監査結果＋全URL・全画像リスト）

### Phase 1 — サイト全面リニューアル（10〜14週間）

> **目的: IA・URL・デザイン・CMSの刷新。課題A-1/A-3/A-4/A-5/A-6の解決**

| 週 | 作業 |
|---|---|
| 1-2 | 要件確定・IA確定・原稿（コンテンツ）方針の決定 |
| 3-4 | ワイヤーフレーム確定 → デザイン（トップ・下層代表3種） |
| 5-6 | デザイン全テンプレート（9種）確定 |
| 5-8 | **原稿作成・写真整理**（発注者作業。ここが最大のボトルネック） |
| 7-10 | CMS構築（WordPress・カスタム投稿タイプ・テンプレート実装） |
| 11-12 | コンテンツ投入・物件/事例データ移行 |
| 13 | 検証（08章4節の受入基準を全件） |
| 14 | リダイレクト設定・公開・公開直後監視 |

**発注者側の作業（これを軽く見ると必ず遅延します）**
- 各ページの原稿確認・修正（特に注文住宅・性能・リフォーム）
- 物件データの整理（既存物件の全項目を新データモデルに合わせて棚卸し）
- 施工事例の写真選定と**価格帯の確定**
- 会社概要の正確な情報（免許番号・許可番号・沿革）
- 性能数値（UA値・C値）の提供 ← **これが最大の差別化要素**

> **写真と原稿は「制作会社が用意してくれる」ものではありません。**
> 工程表上で最も遅れるのがここです。Phase 1 開始と同時に着手してください。

### Phase 3 — 継続運用（公開後 常時）

| 頻度 | 作業 |
|---|---|
| 随時（即日） | 物件の追加・価格改定・ステータス変更 |
| 月2回以上 | 施工事例またはお知らせの追加 |
| 月次 | GA4レポート確認（07章6.4の6項目）、404チェック |
| 四半期 | キーワード順位の確認と、コンテンツ追加計画の見直し |
| 半期 | Core Web Vitals 再測定、アクセシビリティ再監査 |
| 年次 | 会社情報・免許番号の更新、バックアップ復旧リハーサル |

> **更新が止まったサイトは、リニューアル前より価値が下がります。**
> Phase 3 の体制を決めてからPhase 1に着手してください。

## 3. 体制

| 役割 | 担当 | 責務 |
|---|---|---|
| プロジェクトオーナー | 発注者 経営層 | 予算・最終意思決定・原稿の最終承認 |
| Web担当 | 発注者 社内1名 | 窓口、原稿・写真の取りまとめ、公開後の更新 |
| 物件情報担当 | 発注者 営業部門 | 物件データの提供と更新（**即日反映が前提**） |
| PM / ディレクター | 制作会社 | 進行管理、IA、原稿構成 |
| デザイナー | 制作会社 | UI設計、デザインシステム |
| エンジニア | 制作会社 | CMS構築、実装、性能・アクセシビリティ |
| SEO | 制作会社 | キーワード設計、構造化データ、計測設計 |

> **「発注者 社内1名」を必ず決めてください。** 窓口が定まらないプロジェクトは、
> 原稿待ちで停滞します。兼務で構いませんが、週2時間は確保が必要です。

## 4. 概算費用の考え方

具体的な金額は制作会社の見積によりますが、**予算配分の目安**を示します。

| 項目 | 配分目安 | 備考 |
|---|---|---|
| 設計（IA・要件・ワイヤー） | 15% | ここを削ると後工程が倍になる |
| デザイン | 20% | テンプレート9種 |
| CMS構築・実装 | 35% | 物件DB化が主。最大の投資 |
| コンテンツ制作・移行 | 15% | 原稿リライト・データ移行 |
| **写真撮影** | 10% | **別途推奨。ここへの投資対効果は非常に高い** |
| 検証・公開・移行 | 5% | リダイレクト・受入検証 |
| （ランニング） | 月額 | サーバ・ドメイン・保守 |

> **写真への投資を強く推奨します。** 住宅サイトで訪問者が最も見るのは写真です。
> プロのカメラマンによる実邸撮影1棟分の費用は、
> デザインの作り込み数十時間分よりも高い効果を生みます。

## 5. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 原稿・写真の提供遅延 | 公開が1〜2ヶ月遅延 | Phase 1 開始時点で締切を合意。未提供時は仮原稿で進め、後日差し替え |
| 物件データの移行漏れ | 販売機会の損失 | 移行前後で物件件数を突合。営業部門による全件目視確認 |
| **リダイレクト漏れ** | **検索流入の恒久的な損失** | 全URL棚卸しを必須（0-3）。公開後1週間の404監視 |
| 公開直後の順位下落 | 一時的な流入減 | 4〜8週間は様子を見る。慌てて戻さない（07章7節） |
| 公開後に更新が止まる | 投資が無駄になる | Phase 3 の体制を**着手前に**決める。更新しやすいCMSを選ぶ |
| 性能数値（UA値等）が出せない | 差別化訴求が弱まる | 設計事務所・断熱材メーカーと連携して算出。1棟分でも実績値があれば掲載可 |
| 制作会社への過度な依存 | 将来の乗り換え困難 | WordPress採用、ドメイン・サーバは**発注者名義で契約** |

> 最後の項目は必ず守ってください。
> **ドメインとサーバの契約は発注者名義**にし、管理権限を保持してください。
> 制作会社名義だと、将来の乗り換えやトラブル時にサイトを失うリスクがあります。
